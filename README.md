# NPC Dialogue API Template

โครงเซิร์ฟเวอร์บทสนทนาของตัวละคร (NPC) สำหรับเกม เอาไปใส่ตัวละครและเนื้อเรื่องของตัวเองได้เลย ใช้โมเดลภาษาที่รันในเครื่องผ่าน [Ollama](https://ollama.com) ร่วมกับการค้นคืนข้อมูล (RAG) ทำงานออฟไลน์ได้ทั้งหมด

เกมส่งคำถามของผู้เล่นมาที่ `POST /ask` แล้วได้คำตอบของตัวละครกลับเป็น JSON ใช้กับเอนจินไหนก็ได้ที่ส่ง HTTP ได้ เช่น Unreal Engine, Unity, Godot

ใน repo มีตัวละครตัวอย่างหนึ่งตัว (`documents/npc_example`) ให้ดูรูปแบบไฟล์ ลบทิ้งหรือแก้เป็นของตัวเองได้

## ทำอะไรได้

- ตัวละครตอบจากเอกสารที่เขียนให้ ไม่ต้อง fine-tune โมเดล
- เขียน system prompt เองได้ และเปลี่ยนโมเดลได้ ทั้งหมดอยู่ในไฟล์ `meta.json` ของตัวละคร
- ล็อกข้อมูลบางหัวข้อไว้จนกว่าผู้เล่นจะพิมพ์รหัสหรือคำสำคัญ ข้อมูลที่ล็อกจะไม่ถูกส่งเข้าพร็อมต์เลย โมเดลจึงเผลอบอกไม่ได้
- มีหลายตัวละครได้ ตัวละครละหนึ่งโฟลเดอร์
- ตรวจคำตอบของผู้เล่นตามเกณฑ์ที่เขียนไว้ ด้วยโมเดลภาษา (`POST /grade`)

## ติดตั้ง

ต้องมี Python 3.10 ขึ้นไป และ Ollama

```bash
pip install -r requirements.txt

ollama pull bge-m3                              # โมเดล embedding
ollama pull scb10x/typhoon2.5-qwen3-4b          # โมเดลภาษา (เปลี่ยนเป็นตัวอื่นได้)

python app.py
```

เซิร์ฟเวอร์เปิดที่พอร์ต 5005 รอจนขึ้น `WARMUP เสร็จ` แล้วลองถาม

```bash
curl -X POST http://127.0.0.1:5005/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "สวัสดี คุณคือใคร", "npc_id": "npc_example"}'
```

## โครงสร้าง

```
app.py            เซิร์ฟเวอร์และ endpoint
rag_chain.py      แบ่งเอกสาร ค้นคืน เรียก Ollama
grader.py         ตรวจคำตอบของผู้เล่น
settings.py       ค่าตั้งของระบบ (ที่อยู่ Ollama, โมเดลตั้งต้น, พอร์ต)
documents/
  npc_example/    ตัวละครตัวอย่าง คัดลอกโฟลเดอร์นี้ไปแก้ได้
    meta.json     ค่าของตัวละคร: โมเดล, system prompt, หัวข้อที่ล็อก
    info.txt      ฐานความรู้ของตัวละคร
    hints.json    ประโยคสำคัญของเนื้อเรื่อง (ไม่มีก็ได้)
    case_report.json  คำถามและเกณฑ์ตรวจคำตอบ (ไม่มีก็ได้)
```

## สร้างตัวละครของตัวเอง

วิธีเร็วที่สุดคือคัดลอก `documents/npc_example` แล้วเปลี่ยนชื่อโฟลเดอร์ หรือทำเองตามนี้

1. สร้างโฟลเดอร์ `documents/npc_<ชื่อ>/` ชื่อโฟลเดอร์คือ `npc_id` ที่เกมใช้เรียก (ต้องขึ้นต้นด้วย `npc_`)
2. เขียนฐานความรู้ลงไฟล์ `.txt` หรือ `.md` แบ่งหัวข้อด้วยบรรทัด `[ชื่อหัวข้อ]`

   ```
   [ตัวตน]
   ฉันชื่อมีนา เป็นเจ้าของร้านกาแฟหน้าปากซอย

   [คืนวันเกิดเหตุ]
   ร้านปิดสองทุ่ม ฉันเห็นรถสีขาวจอดอยู่หน้าบ้านเลขที่ 12
   ```

3. สร้าง `meta.json` ใส่เท่าที่ต้องการ ที่เหลือใช้ค่าตั้งต้น

   ```json
   {
     "name": "มีนา",
     "model": "llama3.2:3b",
     "system_prompt": [
       "You are มีนา, a coffee shop owner being questioned by a detective.",
       "Answer in Thai, one or two sentences.",
       "Facts come from CONTEXT only. If it is not there, say you do not know."
     ],
     "always_sections": ["ตัวตน"]
   }
   ```

4. รัน `python app.py` ใหม่ หรือเรียก `POST /reload_npcs`

### ค่าใน meta.json

| คีย์ | ค่าตั้งต้น | ความหมาย |
|---|---|---|
| `name` | ชื่อโฟลเดอร์ | ชื่อตัวละคร |
| `model` | ค่าใน `settings.py` | ชื่อโมเดลใน Ollama |
| `system_prompt` | พร็อมต์กลางในโค้ด | ข้อความเดียวหรือลิสต์ของบรรทัด ระบบจะต่อ `CONTEXT:` และเอกสารที่ค้นคืนได้ไว้ท้ายให้เอง |
| `temperature` | 0.2 | |
| `max_tokens` | 80 | ความยาวคำตอบสูงสุด |
| `num_ctx` | 4096 | ขนาดหน้าต่างบริบท |
| `repeat_penalty` | 1.15 | |
| `use_rag` | true | false = ส่งเอกสารทั้งหมดเข้าพร็อมต์ทุกครั้ง |
| `retrieval_k` | 3 | จำนวนหน่วยข้อมูลที่ค้นคืนต่อคำถาม |
| `always_sections` | [] | หัวข้อที่แนบไปทุกคำถาม เช่น บุคลิก กฎของตัวละคร |
| `use_history` / `history_pairs` | true / 4 | จำนวนคู่ถาม-ตอบก่อนหน้าที่ส่งให้โมเดล |
| `fallback_answer` | ข้อความใน `settings.py` | คำตอบเมื่อโมเดลล่มหรือตอบผิดรูป |
| `think` | ปิดอัตโนมัติ | สำหรับโมเดลที่มีโหมดคิดก่อนตอบ |
| `system_as_user` | false | ตั้ง true ถ้าโมเดลไม่รองรับ role system แล้วพ่นพร็อมต์ออกมาแทนคำตอบ |
| `text_fixes` | {} | แทนคำที่โมเดลสะกดผิดประจำ `{"ผิด": "ถูก"}` |
| `keep_alive` | ค่าใน `settings.py` | เวลาที่โมเดลค้างในหน่วยความจำ |
| `locked_sections` | {} | ดูหัวข้อถัดไป |

### ล็อกข้อมูล

```json
"locked_sections": {
  "บันทึกลับ": {
    "code": "ROSE-1987",
    "reveal_keywords": ["กุหลาบแดง"],
    "locked_text": "This section is sealed. Say that a record exists but you cannot open it without the code.",
    "unlock_message": "ยืนยันรหัสแล้ว เปิดบันทึกให้ค่ะ"
  }
}
```

- ชื่อคีย์ต้องตรงกับชื่อหัวข้อ `[บันทึกลับ]` ในเอกสาร
- ระหว่างที่ยังล็อก เนื้อหาจริงของหัวข้อจะถูกแทนด้วย `locked_text` ก่อนส่งเข้าพร็อมต์
- ปลดล็อกเมื่อข้อความของผู้เล่นมี `code` (ไม่สนช่องว่าง ขีด และตัวพิมพ์) หรือมีคำใน `reveal_keywords`
- ข้อมูลที่ต้องการซ่อนต้องอยู่ในหัวข้อที่ล็อกเท่านั้น ถ้าไปปรากฏในหัวข้ออื่นด้วยก็ซ่อนไม่ได้

### hints.json และ case_report.json (ไม่บังคับ)

`hints.json` เก็บประโยคที่เป็นประเด็นสำคัญของเนื้อเรื่อง ทุกครั้งที่ตัวละครตอบ ระบบจะเทียบบทสนทนากับประโยคเหล่านี้ แล้วคืน `hint.triggered` ใน `/ask` เกมเอาไปใช้ได้ เช่น จดลงสมุดบันทึกของผู้เล่น หรือเล่นเอฟเฟกต์

```json
{"threshold": 0.62, "statements": ["ผู้หญิงสวมเสื้อคลุมสีแดงเดินออกจากบ้านเลขที่ 12"]}
```

`case_report.json` เก็บคำถามท้ายเกมและเกณฑ์ตรวจ ใช้กับ `POST /grade`

```json
{
  "pass_mark": 1,
  "questions": [{
    "id": "who",
    "text": "ใครออกจากบ้านเลขที่ 12",
    "hint": "บรรยายลักษณะ",
    "answer": "ผู้หญิงสวมเสื้อคลุมสีแดง",
    "key_facts": ["ต้องระบุว่าเป็นผู้หญิงที่สวมเสื้อคลุมสีแดง"],
    "accept": ["ผู้หญิงเสื้อแดง"],
    "reject": ["ตอบว่าเป็นคุณสมชาย"]
  }]
}
```

เรียกด้วย `{"npc_id": "npc_example", "answers": {"who": "ผู้หญิงใส่เสื้อแดง"}}` คีย์ของ `answers` คือ `id` ของแต่ละข้อ

## เปลี่ยนโมเดล

- เฉพาะตัวละคร: แก้ `"model"` ใน `meta.json`
- ทั้งระบบ: แก้ `CHAT_MODEL` ใน `settings.py` หรือตั้ง environment variable `OLLAMA_MODEL`
- เฉพาะคำขอ: ส่ง `"model": "..."` มากับ `/ask`

โมเดล embedding แก้ที่ `EMBED_MODEL` ดัชนีใน `vector_db/` จะสร้างใหม่ให้เองเมื่อเปลี่ยนโมเดลหรือแก้เอกสาร

ถ้า Ollama อยู่อีกเครื่อง ตั้ง `OLLAMA_URL=http://<ip>:11434`

## API

| Method | Path | Body | ใช้ทำอะไร |
|---|---|---|---|
| POST | `/ask` | `{"question", "npc_id"}` | ถามตัวละคร |
| POST | `/grade` | `{"npc_id", "answers"}` | ตรวจคำตอบของผู้เล่น |
| GET | `/npcs` | | รายชื่อตัวละคร |
| POST | `/reload_npcs` | | อ่าน `meta.json` ใหม่ |
| POST | `/reset_conversation` | `{"npc_id"}` | ล้างประวัติสนทนา |
| GET | `/unlock_state` | | หัวข้อที่ล็อกและปลดแล้ว |
| POST | `/reset_unlocks` | `{"npc_id"}` (ไม่ใส่ = ทุกตัว) | ล็อกกลับ |
| GET | `/health` | | สถานะเซิร์ฟเวอร์และ Ollama |

ตัวอย่างคำตอบของ `/ask`

```json
{
  "answer": "สวัสดีค่ะ คุณตำรวจ ฉันชื่อมีนา เป็นเจ้าของร้านกาแฟปากซอยค่ะ",
  "npc_id": "npc_example",
  "npc_name": "มีนา",
  "hint": {"triggered": false, "score": 0.41, "threshold": 0.62},
  "unlocked": [],
  "locked_sections": ["กล้องวงจรปิดของร้าน"],
  "model": "scb10x/typhoon2.5-qwen3-4b:latest",
  "debug": {"fallback": false, "retrieval_ms": 210.4, "generate_ms": 2950.1}
}
```

`/ask` คืนสถานะ 200 พร้อมข้อความสำรองเสมอแม้โมเดลจะล่ม เกมจึงไม่ค้าง ดูสาเหตุได้ที่ `debug.fallback_reason`

## ข้อจำกัด

- เก็บประวัติสนทนาและสถานะปลดล็อกในหน่วยความจำ แยกตามตัวละคร ออกแบบสำหรับเกมผู้เล่นคนเดียว ปิดเซิร์ฟเวอร์แล้วสถานะหาย
- ค้นคืนด้วยการเทียบ cosine กับทุกหน่วยข้อมูลตรง ๆ เหมาะกับฐานความรู้ขนาดเล็ก (หลักสิบถึงหลักร้อยหน่วย)
- ไม่มีระบบยืนยันตัวตน ควรใช้ในเครื่องหรือในเครือข่ายภายในเท่านั้น
